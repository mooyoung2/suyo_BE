1. 프로젝트 개요
==========


한 줄 정의:
시장 검증이 막막한 예비창업자를 위해 아이템의 리스크를 점수로 진단하고, 직접 물어봐야 할 질문까지 뽑아 주는 AI 시장 검증 도구입니다.

제품 목표:
예비창업자가 시장 진출 여부를 감이 아닌 근거로 판단할 수 있는 상태를 만듭니다.

구체적으로는 세 가지를 달성합니다. 첫째, 인터넷에 존재하는 시장 데이터를 자동으로 수집·환산해 리스크를 구조화된 점수로 제시합니다. 둘째, 데이터로 판단 가능한 영역과 불가능한 영역을 명확히 구분해 사용자가 무엇을 아직 모르는지 인지하게 합니다. 셋째, 확인이 필요한 항목에 대해 검증 질문지를 제공해 실제 확인 행동까지 이어지도록 합니다.

최종적으로는 검증 없이 시장에 진입해 자원을 소진하는 사례를 줄이는 것이 목표입니다.

배경:
폐업한 스타트업의 상당수는 자금이 아니라 시장 이해 부족으로 무너집니다.

CB Insights가 2023년 이후 폐업한 VC 투자 스타트업 431곳을 분석한 결과, 자본 소진이 70%로 1위였으나 이는 최종 사인일 뿐이며 실질적 원인은 제품-시장 적합성 실패 43%, 나쁜 타이밍 29%였습니다. 해당 431개 기업이 폐업 전 조달한 자금은 총 175억 달러로, 자금 부족이 근본 원인이 아니었음을 보여줍니다. 국내에서도 2025년 스타트업 실패 사례 분석에서 제품-시장 부적합이 42%로 나타났습니다.

그러나 시장 검증에 접근할 수 있는 수단은 제한적입니다. 리서치·서베이 대행은 평균 39만원, 온라인 설문 패널은 100명 기준 5만원부터 시작해 초기 팀에게 부담이 됩니다. 반면 정부 창업지원사업 평가에서는 고객 인터뷰 20건, 설문 100건 수준의 검증 증빙을 요구합니다. 검증 수요는 제도적으로 형성되어 있으나 이를 감당할 공급이 부재한 상황입니다.

국내 마케팅 리서치 산업은 2020년 기준 약 7,200억원 규모이며, 1위 사업자의 점유율도 10% 남짓에 불과할 만큼 파편화되어 있어 신규 진입 여지가 존재합니다.

사용자 문제:
예비창업자는 시장 검증이 필요하다는 것은 알지만, 무엇을 어떻게 확인해야 하는지 모릅니다.

사업계획서의 고객 검증 항목을 작성해야 하는 시점에 문제가 드러납니다. 인터뷰 20건이 필요하다는 것은 알지만 대상자를 어디서 구할지 모르고, 어렵게 만나더라도 무엇을 물어야 할지 몰라 결국 제품 아이디어에 대한 의견을 묻게 됩니다. 이렇게 얻은 답변은 대부분 긍정적이지만 실제 판단에는 도움이 되지 않습니다.

근본 원인은 세 가지입니다.

• 방법론의 부재 — 데스크 리서치와 달리 고객조사는 정해진 절차가 없어 스스로 설계해야 합니다.
• 유도질문 편향 — 빠르게 답을 얻고 싶은 심리 때문에 원하는 답이 나오는 질문을 하게 됩니다.
• 접점 부재 — 아직 고객이 아닌 사람은 만날 경로가 없어 결국 지인에게 의존합니다.

그 결과 지인 5명의 의견으로 사업계획서를 작성하고, 검증되지 않은 가정 위에서 개발을 시작하게 됩니다.

해결 방안:
아이템을 입력하면 리스크를 진단하고, 확인이 필요한 항목을 질문지로 만들어 제공합니다.

1단계 · 자동 진단  
시장·경쟁·타이밍·수요 네 개 레이어로 리스크를 분석해 100점 만점 점수를 산출합니다. 레이어 구성은 임의로 정한 것이 아니라 스타트업 실패 원인 통계를 기준으로 설계했으며, 실패 원인 1위인 수요 항목에 최대 배점을 부여했습니다. 인터넷에 존재하는 데이터는 이 단계에서 모두 자동 수집됩니다.

2단계 · 미검증 영역 특정  
수요가 있는지는 데이터로 판단할 수 없습니다. 대신 유사 사례의 존재 여부, 크라우드펀딩 성공·실패 이력, 검색량 대비 실제 거래 데이터 유무를 근거로 수요가 검증되지 않은 정도를 점수화합니다. 이를 통해 사용자가 무엇을 아직 모르는지 명확히 인지하게 합니다.

3단계 · 검증 질문지 생성  
확인이 필요한 항목에 대해 질문지를 자동 생성합니다. 이때 "이런 서비스가 있으면 사용하시겠습니까"와 같은 유도질문을 배제하고, 과거 경험과 실제 행동을 묻는 형태로 설계합니다.

4단계 · 결과 반영  
사용자가 자신의 채널로 질문지를 발송해 응답을 수집하면, 해당 결과가 수요 레이어 점수에 반영되어 최종 진단이 갱신됩니다.

응답자 풀은 직접 운영하지 않습니다. 이를 통해 응답자가 없는 초기 상태에서도 서비스가 정상 작동합니다.

차별점:
무엇을 모르는지 특정하고, 그것을 확인할 방법까지 제공하는 것이 핵심입니다.

기존 AI 도구는 시장에 대해 질문하면 확신에 찬 답변을 제공하지만, 그 판단이 어떤 가정에 기대고 있는지, 무엇이 아직 검증되지 않았는지는 알려주지 않습니다. 또한 유사도 기반으로 동작하므로 동일한 조건을 입력한 사용자는 유사한 결과를 얻게 되어 차별화된 판단 근거가 되기 어렵습니다.

기존 설문 플랫폼은 응답 수집 기능을 제공하지만 질문 설계는 사용자의 몫으로 남깁니다. 무엇을 물어야 할지 모르는 사용자에게는 빈 양식을 제공하는 것과 다르지 않습니다.

본 제품은 그 사이를 연결합니다.

타겟 사용자:
메인 타겟 사용자는 예비창업패키지·창업경진대회·지원사업 등을 준비하며 사업 아이템의 시장성과 고객 수요를 빠르게 검증해야 하는 예비창업자입니다.  
특히 시장조사 경험이 부족해 무엇을 조사하고, 고객에게 어떤 질문을 해야 하는지 어려움을 겪는 초기 창업자를 핵심 사용자로 설정합니다.

사용자 시나리오:
예비창업자가 자신의 창업 아이템을 입력하면 시장·경쟁·트렌드·수요 데이터를 자동 분석해 리스크 점수를 확인합니다.  
이후 데이터만으로 확인할 수 없는 핵심 가설을 바탕으로 고객에게 실제로 물어봐야 할 인터뷰·설문 질문을 자동 생성하고, 조사 결과를 반영해 사업 아이템의 검증 상태를 다시 확인합니다.

핵심 지표:
• 아이템 분석 후 생성된 리스크 진단 사용자 만족도 80% 이상 달성 및 실제 창업 아이디어 검증 과정에서 활용 가능하다는 피드백 확보
• 사용자가 아이템 입력부터 리스크 분석 결과 확인까지 1분 이내에 완료할 수 있도록 구현
• 사용자 테스트를 통해 생성된 질문이 기존 사용자가 직접 작성한 질문보다 구체적이고 검증에 도움이 된다는 피드백 확보

리스크:
• 리스크 점수 산정 기준이 사용자에게 충분히 설득력 있게 전달되지 않을 수 있음
• AI가 생성한 질문이 일부 산업군에서는 실제 검증에 적합하지 않을 가능성이 있음
• 외부 데이터 수집 범위에 따라 분석 결과의 정확도가 달라질 수 있음
• 예비창업자가 실제 인터뷰 및 설문 검증 단계까지 이어지지 않을 가능성이 있음

2. 주요 기능 목록
===========


1. 아이템 분석 요청 생성
===============
[중요도: 높음 | 상태: 작성중]

예비창업자가 자신의 창업 아이템과 기본 맥락을 입력해 시장 검증 분석을 시작할 수 있어야 합니다. 시장조사 경험이 없는 사용자가 짧은 입력만으로 진단을 요청하는 것이 범위이며, 사업계획서 전체를 작성·첨삭하는 기능은 포함하지 않습니다.

[수용 기준]
  1. ○ 사용자는 아이템명, 해결하려는 문제, 예상 고객 및 제공 방식 등 분석에 필요한 기본 정보를 입력할 수 있다.
  2. ○ 필수 정보가 누락된 경우 서비스는 누락 항목을 알려주고 분석 요청을 완료하지 않는다.
  3. ○ 유효한 정보를 제출하면 분석 진행 상태와 결과 확인 경로가 표시된다.
  4. ○ 일반적인 분석 요청은 아이템 입력 시작부터 진단 결과 표시까지 1분 이내에 완료된다.

  1.1 아이템 분석 요청 입력
  ----------------
  [중요도: 높음 | 상태: 작성중 | 사용자 역할: 질문자 | 기기: 웹, Android, IOS]
  [기능의 근거] 시장조사 경험이 부족한 예비창업자가 무엇을 조사해야 하는지 알기 전에, 짧은 아이템 맥락만으로 시장 검증을 시작할 수 있어야 한다.
예비창업자는 창업 아이템명, 해결하려는 문제, 예상 고객, 제공 방식을 입력하여 시장 검증 분석을 요청한다. 이 기능은 입력값의 필수 여부를 검증하고 유효한 요청의 분석 진행 상태와 결과 확인 경로를 제공한다. 사업계획서 전체의 작성이나 첨삭은 포함하지 않는다.
[성공 기준] 아이템 입력 시작부터 리스크 분석 결과 확인까지 일반적인 요청이 1분 이내에 완료된다.
  [개발 준비 슬롯]
  - 선행조건: - 사용자는 분석을 요청할 수 있는 서비스 화면에 접근한다.
  - 트리거: - 사용자가 새 아이템 분석 시작 진입점을 선택한다.
- 사용자가 입력 폼에서 분석 요청 제출을 선택한다.
  - 동작: - 서비스는 아이템명, 해결하려는 문제, 예상 고객 및 제공 방식의 입력값을 수집한다.
- 서비스는 필수 입력값의 누락 여부를 검증한다.
- 유효한 요청이면 분석 작업을 생성하고 진행 상태를 표시한다.
  - 결과: - 유효한 입력으로 분석 요청이 생성된다.
- 사용자는 분석 진행 상태와 진단 결과 확인 경로를 확인한다.
- 분석 요청 이벤트를 기록한다.
  - 예외: - 필수 정보가 누락되면 서비스는 요청을 완료하지 않고 누락 항목을 표시한다.
- 분석 처리 중 오류가 발생하면 서비스는 완료되지 않은 상태와 재시도 안내를 표시한다.
  - 표시: - 입력 화면은 분석에 필요한 기본 정보의 입력 항목을 표시한다.
- 필수값 누락 시 해당 항목별 오류 메시지를 표시한다.
- 요청 제출 후 분석 진행 상태와 결과 확인 경로를 표시한다.
  - 권한 & 접근: - 질문자 역할은 아이템 분석 요청을 생성할 수 있다.
  - 비즈니스 규칙: - 일반적인 분석 요청은 입력 시작부터 진단 결과 표시까지 1분 이내에 완료하는 것을 목표로 한다.
  - 데이터: - 분석 요청은 아이템명, 해결하려는 문제, 예상 고객, 제공 방식 및 처리 상태를 가진다.

    1.1.1 분석 요청 제출
    예비창업자는 아이템명, 해결하려는 문제, 예상 고객과 제공 방식을 입력해 분석 요청을 제출한다. 서비스는 필수 입력값을 확인한 뒤 유효한 요청만 분석 작업으로 등록하고 진행 상태를 보여준다. 사업계획서 작성과 첨삭은 포함하지 않는다.
    └─ 중요도: 높음 | 상태: 작성중 | 사용자 역할: 질문자 | 기기: 웹, Android, IOS
    [개발 준비 슬롯]
    - 선행조건: - 사용자는 새 아이템 분석 입력 화면에 접근한다.
    - 트리거: - 사용자가 분석 요청 제출을 선택한다.
    - 동작: - 서비스는 네 개 입력 항목의 누락 여부를 검증한다.
- 서비스는 유효한 입력으로 분석 작업을 생성한다.
    - 결과: - 분석 요청과 처리 상태가 저장된다.
- 분석 요청 제출 이벤트를 기록한다.
    - 예외: - 필수값이 누락되면 서비스는 요청을 생성하지 않고 항목별 오류를 표시한다.

- 완료된 분석을 선택한 사용자는 기존 진단 결과를 다시 확인한다.
- 분석 목록 조회 및 기존 진단 결과 열람 이벤트를 기록한다.
  - 예외: - 분석 기록이 없으면 서비스는 빈 목록 상태와 새 분석 시작 경로를 표시한다.
- 분석 처리 중 또는 실패한 항목을 선택하면 서비스는 현재 처리 상태 또는 재시도 안내를 표시한다.
  - 표시: - 분석 목록은 아이템명, 분석 처리 상태 및 생성 시점을 항목별로 표시한다.
- 완료, 처리 중, 실패 상태는 서로 구분해 표시한다.
- 빈 목록에서는 새 분석 시작 버튼을 표시한다.
  - 권한 & 접근: - 질문자 역할은 본인 계정에 연결된 분석 기록만 조회할 수 있다.
- 다른 사용자의 분석 기록은 목록과 결과에서 노출하지 않는다.
  - 비즈니스 규칙: - 분석 목록은 최신 생성 시점 순으로 정렬한다.
  - 데이터: - 분석 요청은 연결된 사용자 계정, 아이템명, 처리 상태 및 생성 시점을 가진다.
- 분석 요청은 완료 시 연결된 진단 결과를 참조한다.
